# 节奏按摩引导器（双垫版）· 制作方案

> 依据：《PRD.md》(核心 PRD · 双垫版)
> 一句话定位：一个**纯本地、零后端、零操作**的移动端网页应用 —— 以双硅胶垫为工具，按「引诱→蓄力→攀爬→释放→回落」螺旋模型生成编排，用强弱节拍音引导四模式切换与双侧对称度，**息屏可播、结束留档**。
> **已拍板新增**：触觉振动反馈（按节拍振动、息屏时作为主要感知反馈），详见 §5.6 / §7 / §12。

---

## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│  UI 层  Home(编排) / Player(播放) / History / Favorites /     │
│         Settings / Landing(静默着陆)                          │
├─────────────────────────────────────────────────────────────┤
│  会话/播放控制器  StateMachine：warmup→core→sprint→landing→    │
│                  finish；进度保存、扣屏暂停、2h 恢复            │
├─────────────────────────────────────────────────────────────┤
│  音频引擎  Web Audio：6 音色合成 / lookahead 调度 / 左右声道分离  │
│           / 70:30 音量 / 阶段过渡信号 / 振动脉冲(§5.6)           │
├─────────────────────────────────────────────────────────────┤
│  编排引擎(纯 TS，可单测) 时长分配 / 螺旋单元 / 冲刺 / 硬性规则守卫 │
├─────────────────────────────────────────────────────────────┤
│  存储层  localStorage(偏好) / IndexedDB(历史+收藏) /           │
│          sessionStorage(进度)                                 │
└─────────────────────────────────────────────────────────────┘
```

数据流（唯一主链路）：

```
设置总时长(+偏好) → 编排引擎(seeded) 生成 Orchestration
  → 预览(统计+单元列表) → 开始
  → 播放器全自动推进(热身→核心单元×n→冲刺→收尾)
  → 静默着陆 60s → 可选评分/收藏 → 历史落盘 → 复盘/再播
```

**架构原则**

- **分层解耦**：编排引擎是纯函数（输入时长+设置+seed → 输出完整编排对象），与 UI/音频完全无关 → 单测覆盖全部领域规则。
- **时钟权威**：播放计时以 `AudioContext.currentTime` 为基准（息屏/后台不随节流漂移），墙钟仅用于进度持久化。
- **纯本地**：无后端、无外部资源、无音频文件依赖（合成音色零资产）。

## 2. 技术选型

| 项   | 选型                                        | 理由                                                            |
| --- | ----------------------------------------- | ------------------------------------------------------------- |
| 框架  | React 18 + TypeScript                     | 类型化领域模型；组件化 5 页面；workspace 痕迹显示既有部署为 React 产物                 |
| 构建  | Vite                                      | 快、产物为纯静态，适配 GitHub Pages                                      |
| 音频  | Web Audio API                             | 6 音色实时合成、StereoPanner/ChannelMerger 做左右分离；零依赖零资产              |
| 存储  | localStorage / IndexedDB / sessionStorage | 与 PRD §4.10 强制一致                                              |
| 触觉  | `navigator.vibrate`（Web Vibration API）   | 用户已拍板加入；息屏/锁屏时的核心可感知反馈（Android 支持；iOS 降级，见 §5.6/§9-9） |
| 部署  | GitHub Pages（静态 SPA）                      | 证据：`.reasonix` 中已抓取 `wait2050.github.io/speed` 的 React bundle |
| 可选  | PWA manifest + 全屏 API                     | 提升「像 App 一样」体验；离线缓存整包                                         |

> 若后续确认优先序，「框架」一项可整体替换为 Vue/Svelte 而不影响领域层设计（引擎是纯 TS）。

## 3. 数据模型（核心类型）

```ts
// ── 领域基础 ──
type Mode     = 'areola-friction' | 'light-touch' | 'press-release' | 'full-cover';
type Symmetry = 'full-asymmetric' | 'biased' | 'full-symmetric' | 'staggered';
type Timbre   = 'classic' | 'woodfish' | 'heartbeat' | 'waterdrop' | 'fingertip' | 'bassdrum';
type Side     = 'L' | 'R';
type StageName= 'seduce' | 'charge' | 'climb' | 'release' | 'cooldown';

interface SideSpec {
  mode: Mode; bpm: number; timbre: Timbre;
  direction?: 'cw' | 'ccw';        // 全覆盖滑动/旋转方向（随机）
  dominant?: boolean;              // 是否主导侧
}

interface UnitStage {
  name: StageName;
  durationMs: number;
  symmetry: Symmetry;
  dominant: Side;                  // 该阶段主导侧
  left: SideSpec; right: SideSpec;
  cue?: 'approach-seduce-end' | 'approach-release' | 'approach-cooldown'
      | 'handoff' | 'none';        // §4.7 声音信号标记
}

interface Unit {
  index: number;
  stages: UnitStage[];             // 固定 5 段：seduce→charge→climb→release→cooldown
  releaseDurationMs: number; releaseBpm: number;
  climbSymmetry: Symmetry; releaseSymmetry: Symmetry;
}

interface SprintSub { name: 'pushoff'|'ramp'|'peak'|'plateau'|'taper';
                      durationMs: number; bpmStart: number; bpmEnd?: number;
                      symmetry: Symmetry; left: SideSpec; right: SideSpec; cue?: ... }

interface Orchestration {
  id: string; seed: number; createdAt: number; totalMs: number; totalSec: number;
  warmup: { durationMs: number; stages: UnitStage[] };   // 对称摩擦+轻度交替, 60BPM
  core: Unit[];                                          // 2~4 个螺旋单元
  sprint: { substages: SprintSub[] };                    // 起冲/加速/波峰/高位/收尾
  landing: { durationMs: number };                       // 60s 静默着陆（不计入 totalMs，见 §12-2）
  transitions: { atMs: number; durMs: number; kind: string }[]; // 各 3s
  stats: { totalSec; stimSec; restSec; unitCount; warmupUnits; coreUnits; sprintSteps };
}
```

## 4. 编排引擎设计（重点 · 含硬性规则）

### 4.1 输入

- `totalSec`（1–60 分钟）
- `settings`：四档 BPM(慢60/中105/快120/极速135，40–200 可调)、各档音色、乳晕缓冲区间(10–30s)、收尾音色
- `seed`（用户点「重新编排」时换新 seed；同 seed 可复现）

### 4.2 时长分解与可行性下界

```
totalMs = warmupMs + coreMs + sprintMs + Σtransitions(每次 3s)
静默着陆 60s 附加、不计入 totalMs（见 §12-2，可改为计入）
warmup = 20% × T，sprint = 20% × T，core = 60% × T（按比例，随后迭代微调到精确匹配）
transitions 段数 = 1(热身→核心) + (n-1)(单元间) + 1(核心→冲刺) + 1(冲刺→收尾?) = n+2 段
```

- 核心单元数：`n = clamp(round(coreSec / 165), 2, 4)`（单元基准 ~2.75min）。
- **可行性守卫**：单单元最小 ≈ 25+20+30+40+15 = 130s（阶段下限）；热身/冲刺各自有最小结构。
  - **已拍板（§12-3）**：引擎按规则下限计算 `minFeasibleSec`，并在编排对象中返回；若 `T < minFeasibleSec`，**拒绝生成**并在 UI 提示最小可生成时长 —— 不采取压缩阶段/减单元的静默违规路径，严格保留六条硬性规则。

### 4.3 相位模板（§4.1 的结构落地）

- **热身**：双侧对称乳晕摩擦 + 双侧对称轻触**交替**，60BPM，占 `warmupMs`。
- **核心**：`n` 个螺旋单元串联，单元间 **3s 乳晕摩擦回落过渡**（满足硬性规则 3）。
- **冲刺**：起冲/加速/波峰/高位持续/收尾 五子段，基准 40/50/60/60/15s，按 `sprintMs/225` 等比例缩放后 round 到秒并回填差值到「高位持续」段。
- **收尾子段**：双侧对称轻触 3–5 次 → 乳晕摩擦 5s → 移开。
- **静默着陆**：固定 60s（前 30s 心跳 60→0 减速，后 30s 完全静默 + 呼吸灯动画），不参与总时长。

### 4.4 螺旋单元生成（§4.2/§4.3）

每个单元五阶段**固定顺序**：`seduce → charge → climb → release → cooldown`。

| 阶段  | 基时      | 左        | 右     | 对称度   | 说明               |
| --- | ------- | -------- | ----- | ----- | ---------------- |
| 引诱  | 25–35s  | 轻触(主导侧)  | 乳晕摩擦  | 完全非对称 | **禁止双侧同模式**（规则2） |
| 蓄力  | 20–30s  | 摩擦→点按    | 摩擦→点按 | 完全对称  | 同步过渡             |
| 攀爬  | 30–40s  | 全覆盖(主导侧) | 点按-松开 | 偏对称   | 追逐感              |
| 释放  | 40–60s↑ | 全覆盖      | 全覆盖   | 完全对称  | 双耳统一重拍           |
| 回落  | 15–20s  | 乳晕摩擦     | 乳晕摩擦  | 完全对称  | ≥10s 双侧复位（规则3）   |

- **主导侧轮换（规则5）**：奇数单元左主导、偶数右主导；且当前单元引诱段主导侧 = 上一单元引诱段主导侧之反。
- **螺旋递进（§4.3 三维）**：单元 i 的释放时长 = 40 + 10×(i-1)（40/50/60/50），释放 BPM = 105/120/135/135；每单元 释放时长递增 或 BPM 升档（二选一或同时）；释放对称度恒为完全对称。
- **随机性边界（规则1）**：仅体现在①各阶段时长 ±20% 抖动 ②释放滑动方向 cw/ccw。**其余结构一律固定**。
- 单元时长计算：先按模板基准（含递进后的释放时长）求和 → 与 `coreSec/n` 的比例缩放 → 逐阶段 round 并回填差值（优先回填到「回落保底 10s」之后的余量）。

### 4.5 冲刺子结构（§4.4 落地）

| 子段           | 时长  | 构成                                                      |
| ------------ | --- | ------------------------------------------------------- |
| 起冲 pushoff   | 40s | 完全对称全覆盖 105BPM → 偏对称(左20s) → 偏对称(右20s)                  |
| 加速 ramp      | 50s | 完全对称全覆盖旋转，BPM 105→120 线性递增；每 10s 插 2s 微非对称（左退点按、右保持全覆盖） |
| 波峰 peak      | 60s | 交错对称：左 全覆盖6s→点按3s→…；右 点按3s→全覆盖6s→…；两侧错开半相位；135BPM       |
| 高位持续 plateau | 60s | 完全对称全覆盖慢滑，BPM 120→105 渐降                                |
| 收尾 taper     | 15s | 对称轻触 3–5 次 → 乳晕摩擦 5s → 移开                               |

- **规则4 守卫**：冲刺段全程禁止 `areola-friction`（波峰复位用交错对称替代）。
- 缩放逻辑见 4.3；「微闪避」为内部微事件序列，随 ramp 子段整体缩放。

### 4.6 硬性规则守卫（validator，独立纯函数）

PRD §4.5 六条逐条实现为不可变式断言，`generator` 产出后**必须过校验**才可返回，单测覆盖：

1. `stageOrder === ['seduce','charge','climb','release','cooldown']`（每单元）
2. seduce 阶段：`left.mode !== right.mode`，主导侧 = 轻触、辅助侧 = 乳晕摩擦
3. 任何高强度阶段（climb/release/冲刺子段）之后：cooldown/过渡必须双侧对称乳晕摩擦 **≥10s**
4. sprint 子段 `mode ∈ {light-touch, press-release, full-cover}`，禁止摩擦
5. 相邻单元 dominant 不同（含 seduce 段主导侧轮流）
6. `|Σ阶段时长 + Σ过渡 - totalMs| ≤ 5s`

### 4.7 预览统计

来自 Orchestration 派生：总时长 / 刺激总时长（非摩擦阶段）/ 休息总时长（摩擦+回落+过渡）/ 总单元数 / 热身N / 核心N / 冲刺步数，供首页统计卡与单元列表渲染。

## 5. 音频引擎设计

### 5.1 六音色实时合成（零资产）

- 每个音色 = 一次短合成（OscillatorNode/GainNode 包络），采样为一击式或短循环。
  - 经典嗒音：方波短脉冲 + 快速衰减
  - 木鱼：三角波 ~800Hz + 谐振，闷
  - 心跳：低频正弦「咚-咚」双拍（BPM 语义）
  - 水滴：正弦滑频微升 + 极快衰减
  - 指尖敲击：噪声/方波 短促瞬态
  - 低音鼓点：正弦低频 + 指数衰减 + 短噪声打击面
- 每个音色预生成 1 个「原语 buffer」（或每次命中即时合成），命中节点复用源以减少 GC。

### 5.2 节拍调度器

- **lookahead scheduler**：`setInterval(25ms)` 轮询 `AudioContext.currentTime`，每次把未来 0.1–0.2s 窗口内的节拍事件排入 `AudioBufferSourceNode`。
- **抗节流加固**：lookahead 窗口放大到 5–10s、配合 `visibilitychange` 唤醒后**重锚定**（resume + 补排），以承受息屏/后台的 timer 节流。
- 节拍事件在播放前一次性由 Orchestration 展开为闭式时间线（见 §5.5）。

### 5.3 左右声道分离与 70:30 音量

- 双侧同模式：单声道中置播放对应音色节拍。
- 双侧不同模式（引诱/攀爬/波峰）：**左声道=左侧指令、右声道=右侧指令**（ChannelMerger 汇入立体声输出，或对每击事件用 StereoPanner ±1）。
- 音量比 = 主导侧 70% : 辅助侧 30%；主导侧交接（单元轮换、冲刺内左右切换）时在 **3s 内线性交叉淡化**。
- BPM 各自独立（如左 105 右 135），节拍相位错开以实现「追逐/错峰」听感。

### 5.4 阶段过渡信号（§4.7）

- 每阶段首尾注入 cue 事件：热身→核心「叮」(音色库整体切换)、核心→冲刺「叮叮」、主导侧交接柔和「叮」、冲刺→收尾静默 1s、释放尾 5s 重拍渐慢渐轻、引诱尾 5s 连音渐弱/轻拍渐强、攀爬尾 5s 辅助侧中拍渐升重拍、收尾→着陆心跳 60→0 减速 30s。
- 实现为时间线中的特殊事件（改变后续节拍的 gain/envelope 参数），由调度器消费。

### 5.5 息屏/锁屏可靠播放（关键决策 · 已拍板：方案 A hybrid）

PRD 要求「≤30 分钟预渲染为音频文件；>30 分钟实时节拍调度」。

**技术现实**：

- 30min 立体声 f32 WAV ≈ **635MB**（44.1kHz×2ch×4B×1800s），即使 16bit 也 ≈318MB，直接渲染全程「音频文件」**不可行**；且节拍是稀疏音，大量是静音，渲染全程是对资源的浪费。
- 另一方面，Web Audio 在部分移动浏览器（尤其 iOS 锁屏）会被挂起，要实现「锁屏仍播」，最稳的是 `<audio>` 元素播放**真音频文件**（iOS 对 audio 后台播放支持优于 WebAudio）。

**建议方案（hybrid，两层兜底）**：

1. **预渲染「紧凑节拍时间线」**（事件数组：时刻/侧/音色/BPM/音量/方向），无论长短都先展开为时间线 —— 这是 PRD「预渲染」语义的实现化（**不是**音频文件）。
2. **短会话（≤~15min）**：用 `OfflineAudioContext` 将时间线一次性渲染成**低码率 WebM/Opus（可接受几 MB 内）**，交给 `<audio>`，→ 锁屏/息屏**最稳**。
3. **长会话（>~15min 或 >30min）**：Web Audio 实时调度 + 大 lookahead + Wake Lock + 唤醒重锚定，接受平台级锁屏限制。
4. 兜底：`visibilitychange` 时若 `ctx.state==='suspended'` → `ctx.resume()`。

▶ **已拍板：采用方案 A（hybrid）**。备选演进：若上线后实测「锁屏持续播放」为硬需求且不愿接受压缩，可升级为方案 C（全程 `<audio>` + 分片 Opus），体积可控。

### 5.6 振动脉冲（已拍板新增）

- **目标**：息屏/锁屏时声音不可靠的平台，以触觉维持「节奏引导」的主反馈；有屏时作为节拍与阶段信号的听觉增强。
- **机制**：调度器把节拍事件同源复制一份给「振动队列」——每次节拍命中（可合并）调用 `navigator.vibrate(pattern)`：
  - 轻触/水滴 = 短单脉冲 `[15]`
  - 点按-松开 = 中长脉冲 `[30]`
  - 全覆盖/心跳 = 强脉冲组 `[40, 30, 40]`
  - 阶段过渡 cue（叮/叮叮/交接） = 专用区分模式 `[60]` / `[60, 60, 60]` / `[40, 40, 40]`，与节拍脉冲区分
- **节流与限幅**：两拍间隔 <100ms 时合并为一次；单次 ≤400ms、每 10s 总振动时长限幅，防马达过热/耗电。
- **平台差异**：Android Chrome 全面支持；iOS Safari 不支持 `navigator.vibrate`（自动无操作，**降级路径**见风险 §9-9）。播放前检测 `'vibrate' in navigator`，不支持则不调度、静默降级。
- **设置项**：总开关（默认开）+ 强度档（弱/标准/强 = 脉冲时长系数 0.5/1/1.5）。息屏时作为主反馈，不依赖屏幕、不破坏「零操作」。

## 6. 播放器与会话控制

### 6.1 状态机

```
PREVIEW ──[start]──▶ PLAYING ──[完成]──▶ LANDING ──[提前结束/60s到]──▶ FINISHED
                      │ ▲                       │
                      └─[paused]──▶ PAUSED──────┘ (resume)
                      │
                      └─[中断/退出]──▶ 写 sessionStorage → 下次打开 2h 内询问
FINISHED ──[评分/收藏]──▶ 历史落盘 ──▶ 返回首页(或复盘)
```

- 计时权威 = `AudioContext.currentTime`；每 5s 将 `{id, seed, elapsedMs, phaseIdx, stageIdx, savedAt}` 写入 `sessionStorage`。
- 扣屏暂停 / 翻转继续：`deviceorientation` 判定面朝下(γ 近似 ±90) → pause；朝上 → resume（需用户手势授权；iOS 权限受限时**降级**为「点按播放页大区域暂停/继续」）。PRD §3.2 表述为「可选」，实现上作为设置开关（风险见 §9-3）。

### 6.2 播放 UI

- 当前阶段名称 + **圆形倒计时**（SVG stroke-dashoffset，剩余秒数）
- 对称度徽标（对称/偏对称/非对称/交错）+ **主导侧指示 L/R**
- 双侧模式/方向小字提示；呼吸灯动画用于静默着陆（CSS 周期性 opacity 渐变，60s：前 30s 同步心跳减速、后 30s 纯动画）
- **振动指示角标**：当前振动模式（轻/中/强）+ 鸣响（播放中被强节拍打断不影响）——息屏时此页静默，振动即反馈（§5.6）

### 6.3 恢复

- 打开即检测 `sessionStorage`：未完成且 `now - savedAt < 2h` → 弹窗「继续 / 放弃」；继续则跳转第 N 阶段，放弃则清除并回首页。

## 8. 存储设计（PRD §4.10 强制，纯本地）

- `localStorage`：`speed.prefs.v1` { speeds:[{bpm,timbre}×4], areolaMin/Max, endTimbre, defaultDuration, haptics:{enabled, intensity:'weak'|'standard'|'strong'} }
- `sessionStorage`：`speed.session.v1`（见 6.1，正常结束/放弃即清除）
- `IndexedDB` `speed-db` v1：
  - store `history`：keyPath `id`，index `createdAt`；字段 {id, seed, totalSec, unitCount, rating?, favorite?, createdAt, orchestration(快照)}
  - store `favorites`：keyPath `id`；字段 {id, name, orchestration, createdAt}
  - 「历史保留最近 20」由写入时截断维护；「清空全部数据」= 清三处 + IndexedDB 删除库。

## 9. 风险与对策

| #   | 风险                        | 影响           | 对策                                                                 |
| --- | ------------------------- | ------------ | ------------------------------------------------------------------ |
| 1   | 锁屏/息屏播放被平台挂起（尤其 iOS）      | 核心体验「息屏可播」受损 | hybrid 方案：短会话 `<audio>` 真音频；长会话 Wake Lock+重锚定；文档化平台差异（见 5.5/§12-1） |
| 2   | 「30min 预渲染音频文件」物理不可行      | PRD 原文无法照做   | 解释为「预渲染节拍时间线」+ 低码率 Opus；**已拍板（§12-1）**                              |
| 3   | 扣屏暂停依赖传感器权限（iOS 需授权、误触率高） | 交互不达预期       | 降级为点击暂停；设置开关；传感器 debounce + 仅锁定时生效                                 |
| 4   | 时长过短(<~8min)无法容纳 2 个最小单元  | 生成失败         | **已拍板（§12-3）**：按规则下限返回 `minFeasibleSec`，UI 提示最小可生成时长并拒绝生成                                       |
| 5   | timer 节流导致节拍漂移            | 节奏不稳         | 时钟以 AudioContext 为准；大 lookahead 窗口；唤醒重锚定                           |
| 6   | 音色在低端机 CPU 抖动             | 掉帧/爆音        | 原语 buffer 复用；OfflineAudioContext 预渲染短会话；节流合成                       |
| 7   | IndexedDB 写入阻塞主线程         | UI 卡顿        | 异步写入 + 快照序列化在结束阶段（非播放中）执行                                          |
| 8   | 后台音频权限策略差异                | 首击无声         | 一律始于用户手势的「开始播放」点击，`ctx.resume()` 后才调度                              |
| 9   | `navigator.vibrate` 平台差异（iOS 不支持；低端机振动马达弱） | 息屏反馈缺失/耗电 | 播放前探测 `'vibrate' in navigator`，不支持的平台静默降级（依赖音频）；脉冲限幅防止过热耗电；设置提供开关+强度 |

## 11. 测试策略

- **单元（Jest/Vitest）**：编排引擎 —— 时长约束网格、六规则不变量、主导侧轮换、阶段顺序、冲刺无摩擦断言、seed 可复现 + 不同 seed 变异。

- **息屏模拟**：DevTools 后台节流 + visibilitychange 恢复；真机(Android+iOS)锁屏实测。

- **性能**：30min 编排内存上界、调度器漂移 <50ms、低端机合成 CPU。

## 12. 决策记录（已拍板，作为实现约束）

| # | 决策项 | 已拍板结论 |
|---|------|---------|
| 1 | 「预渲染为音频文件」落地方案 | **A. hybrid**：统一预渲染节拍时间线；≤~15min 用 OfflineAudioContext 渲染低码率 Opus 交 `<audio>`（锁屏最稳）；更长会话 Web Audio 实时调度 + Wake Lock + 重锚定。备选演进方案 C（全程 `<audio>` 分片 Opus）保留 |
| 2 | 静默着陆 60s 是否计入总时长 | **不计入**：总时长 = 热身+核心+冲刺+阶段过渡(3s×n+2)；着陆为收尾后附加 60s |
| 3 | 过短时长的处理策略 | **提示最小可生成时长**（保留规则下限）：引擎返回 `minFeasibleSec`，不足时 UI 提示并拒绝生成；不做「压缩到下限减单元」的静默违背规则路径 |
| 4 | 技术栈 | **React + TypeScript + Vite + Web Audio API**，纯静态 SPA 部署 **GitHub Pages**（PWA manifest + 全屏可选） |
| 5 | 触觉振动反馈 | **加入，默认开启**：`navigator.vibrate` 随节拍/阶段 cue 振动（映射见 §5.6），提供开关 + 弱/标准/强三档；不支持的平台（iOS）静默降级 |
